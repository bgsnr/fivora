Audit komprehensif dilakukan terhadap seluruh antarmuka (landing page, autentikasi, dashboard admin, manajemen laporan mahasiswa/petugas), komponen UI, file style, alur navigasi, skema database, serta mekanisme validasi client dan server.

Total temuan: **24 temuan**
- **Prioritas TINGGI (Hard Gate & Integritas Fungsional)**: 14 temuan (No. 01 - 14)
- **Prioritas SEDANG (Purpose-Gate & Elemen Visual)**: 5 temuan (No. 15 - 19)
- **Prioritas RENDAH (Quality Locks & Konsistensi Desain)**: 5 temuan (No. 20 - 24)

## Daftar Temuan Lengkap

### Prioritas TINGGI (Hard Gate — Wajib Lolos Tanpa Pengecualian)

#### 01. [R-02] Penggunaan Karakter Em Dash (`—`) pada Tampilan Admin & DESIGN.md
- **Lokasi**: `app/admin/admin-dashboard.tsx:617`, `DESIGN.md:5`
- **Aturan**: R-02 (Copywriting — Dilarang menggunakan em dash `—` di seluruh teks UI).
- **Alasan**: Di `admin-dashboard.tsx`, jumlah fasilitas ditampilkan dengan `<strong>—</strong>`. Di `DESIGN.md` terdapat kalimat template `decks — all while staying on brand`. Wajib diganti dengan tanda hubung biasa, tanda kurung, titik dua, atau teks penjelas.

#### 02. [R-24 / R-26 / C-2] Link Navbar/Footer/Hero Mengarah ke Rute Mati `/reports` (404)
- **Lokasi**: `components/landing/hero.tsx:61`, `components/landing/footer.tsx:69`
- **Aturan**: R-24 (Navigation), R-26 (Interactive Elements), C-2 (Functional Completeness).
- **Alasan**: Tombol "Lapor Kerusakan" di Hero dan tautan di Footer mengarah ke `/reports`. Rute yang sebenarnya ada di Next.js App Router adalah `/laporan`. Pengguna akan mengalami error 404 saat mengklik tombol utama ini.

#### 03. [R-24 / R-26 / C-2] Pengalihan Rute Mati Pasca-Login Petugas (`/operator`) dan Pengguna (`/dashboard`)
- **Lokasi**: `app/login/page.tsx:122`, `app/login/page.tsx:126`
- **Aturan**: R-24 (Navigation), R-26 (Interactive Elements), C-2 (Functional Completeness).
- **Alasan**: Setelah login berhasil, role `petugas` diarahkan ke `router.push('/operator')` dan role `pengguna` diarahkan ke `router.push('/dashboard')`. Kedua halaman tersebut belum dibuat (404 Not Found). Untuk petugas rutenya adalah `/petugas/laporan`.

#### 04. [R-24 / R-26 / C-2] Link Dead Destination `/reservations` pada Katalog Fasilitas
- **Lokasi**: `components/landing/facility-showcase.tsx:345`
- **Aturan**: R-24 (Navigation), R-26 (Interactive Elements), C-2 (Functional Completeness).
- **Alasan**: Tombol "Reservasi" dan "Periksa Jadwal" mengarah ke `/login?redirect=/reservations?facilityId=...`, padahal halaman `/reservations` belum diimplementasikan di `/app`. Selain itu, tombol fasilitas yang berstatus `maintenance` (disabled) tetap terbungkus tag `<Link>` aktif sehingga tetap dapat diklik.

#### 05. [R-26 / C-2 / AGENTS.md] Formulir Buat Laporan Tidak Menyimpan Data ke Server (Dead Form)
- **Lokasi**: `app/laporan/buat/page.tsx:72-103`
- **Aturan**: R-26 (Interactive Elements), C-2 (Functional Completeness), AGENTS.md (Server Validation & Storage).
- **Alasan**: Fungsi `handleSubmit` hanya memvalidasi input di client lalu menampilkan pesan sukses lokal tanpa mengirim data ke Server Action/API, tanpa upload foto ke Supabase Storage, dan tanpa insert ke database Supabase.

#### 06. [R-26 / C-2 / AGENTS.md] Alur Penanganan Laporan Petugas Tersimpan di LocalStorage Browser
- **Lokasi**: `app/petugas/laporan/page.tsx`, `app/petugas/laporan/[id]/page.tsx`, `lib/use-demo-reports.ts`
- **Aturan**: R-26 (Interactive Elements), C-2 (Functional Completeness), AGENTS.md (Penyimpanan Riwayat Terpusat).
- **Alasan**: Petugas memproses status laporan (diproses/selesai/ditolak) dan catatan petugas hanya tersimpan di `window.localStorage` (`fivora-demo-reports-v1`), bukan di database Postgres Supabase. Jika browser ditutup atau berganti perangkat, data hilang.

#### 07. [R-27 / C-4] Ketiadaan Empty State, Loading State, dan Error State yang Resilien
- **Lokasi**: `app/laporan/page.tsx`, `app/admin/page.tsx`, `app/petugas/laporan/page.tsx`
- **Aturan**: R-27 (UI States), C-4 (Resilience).
- **Alasan**: 
  - `app/laporan/page.tsx` langsung melakukan `.map()` tanpa tampilan saat riwayat laporan kosong (`reports.length === 0`), serta tidak memiliki `loading.tsx` / `error.tsx`.
  - `app/admin/page.tsx` menangkap kegagalan query database hanya via `console.error` lalu mengirimkan array kosong tanpa feedback visual error ke antarmuka admin.

#### 08. [R-03 / C-4] Menu Navigasi Hilang Sepenuhnya pada Layar Mobile
- **Lokasi**: `components/landing/navbar.tsx:20`
- **Aturan**: R-03 (Mobile Responsiveness), C-4 (Resilience).
- **Alasan**: Navigasi menggunakan class `hidden md:flex` tanpa menyediakan tombol hamburger menu, drawer, atau collapsible nav untuk layar smartphone (<768px). Pengunjung via mobile tidak dapat membuka Katalog, Ketentuan, ataupun Alur Layanan.

#### 09. [R-32] Modal Tambah Operator & Pengguna Tidak Dapat Ditutup dengan Tombol Escape
- **Lokasi**: `app/admin/admin-dashboard.tsx:867`, `app/admin/admin-dashboard.tsx:1015`
- **Aturan**: R-32 (Keyboard Accessibility).
- **Alasan**: Modal hanya mendengarkan klik backdrop `onMouseDown`, tanpa event handler tombol `Escape` pada keyboard dan tanpa focus trap. Pengguna keyboard tidak dapat menutup modal tanpa bantuan mouse.

#### 10. [R-34] Skema Dark Mode Broken / Terpecah (Hardcoded Light di Seluruh Module)
- **Lokasi**: `app/globals.css:87-120`, `login.module.css`, `register.module.css`, `admin-dashboard.module.css`, `laporan.module.css`
- **Aturan**: R-34 (Every Theme You Ship Must Work).
- **Alasan**: `globals.css` mendeklarasikan variabel warna `.dark`, namun tidak ada komponen toggle tema. Seluruh CSS module dan komponen landing page menggunakan warna hardcoded putih/terang (`#ffffff`, `#f9f9f9`, dll.) sehingga jika mode gelap diaktifkan, antarmuka akan rusak dan kontras teks bertabrakan.

#### 11. [R-38 / R-17 / C-5] Data Dummy Statis Ditampilkan Seolah-olah Real-Time Status
- **Lokasi**: `components/landing/hero.tsx:106-199`, `components/landing/facility-showcase.tsx:32-105`
- **Aturan**: R-38 (Real Content or Honest Placeholder), R-17 (Data & Numbers), C-5 (Evidence Over Claims).
- **Alasan**: "Papan Monitoring Ketersediaan (HARI INI)" di Hero memakai indikator pulse hijau dengan data statis hardcoded, bukan query ketersediaan nyata dari database. Di showcase fasilitas, data hardcoded `REAL_FACILITIES` ditampilkan tanpa penanda atau koneksi ke tabel `facilities`.

#### 12. [AGENTS.md / Keamanan] Ketiadaan File `middleware.ts` untuk Otorisasi Rute Berbasis Peran
- **Lokasi**: Root project (ketiadaan `middleware.ts`)
- **Aturan**: AGENTS.md (Proteksi route berdasarkan role).
- **Alasan**: Tidak ada proteksi rute di layer Next.js Middleware. Halaman `/petugas/laporan` atau `/laporan` dapat diakses langsung via URL oleh siapapun tanpa pemeriksaan sesi login di edge.

#### 13. [AGENTS.md / Arsitektur] Query Supabase Langsung di Komponen Client Login
- **Lokasi**: `app/login/page.tsx:61`
- **Aturan**: AGENTS.md (Pemisahan tanggung jawab & konvensi kode: "Jangan taruh logic query Supabase langsung di komponen UI — lewat /lib/actions").
- **Alasan**: Setelah sign-in berhasil, komponen client melakukan query `supabase.from('users').select(...).eq('auth_user_id', ...)` langsung di sisi browser alih-alih melalui Server Action atau session helper.

#### 14. [AGENTS.md / Keamanan DB] Tabel Inti Belum Dibuat & 8 Tabel Rentan Tanpa RLS di Supabase
- **Lokasi**: Database Supabase Postgres (`public` schema)
- **Aturan**: AGENTS.md (Skema Data & Otorisasi RLS).
- **Alasan**:
  - Tabel `facilities`, `reservations`, dan `reports` **belum ada** di database Supabase.
  - Terdapat 8 tabel sisa framework lama (`migrations`, `password_reset_tokens`, `sessions`, `cache`, `cache_locks`, `jobs`, `job_batches`, `failed_jobs`) dengan status **RLS Disabled**, menimbulkan celah keamanan kritis di mana pengguna anonim dapat mengaksesnya.

### Prioritas SEDANG (Purpose-Gate — Diizinkan Jika Memiliki Alasan Tertulis)

#### 15. [R-01] Gradien Ungu AI-Default pada Halaman Login & Registrasi
- **Lokasi**: `app/login/login.module.css:69`, `app/register/register.module.css:58`
- **Aturan**: R-01 (Color & Gradients), DESIGN.md (Anti-Slop Guardrails).
- **Alasan**: Menggunakan `linear-gradient` warna ungu (#8147e6 ke #8b63c7) sebagai latar samping tanpa tujuan hierarki yang jelas. Hal ini secara eksplisit dilarang dalam panduan proyek: *"no artificial purple gradients or floating blobs"*.

#### 16. [R-08] Ikon Panah Dekoratif (`ArrowUpRight`) pada Tombol Non-Eksternal
- **Lokasi**: `components/landing/hero.tsx:68`, `components/landing/operating-hours.tsx:92`
- **Aturan**: R-08 (Button Arrows).
- **Alasan**: Tombol internal "Lapor Kerusakan" dan "Daftar Pengguna Baru" disematkan ikon panah serong (`→` / `↗`) murni sebagai hiasan, bukan menunjukkan tautan ke situs luar.

#### 17. [R-09] Eyebrow Badges di Atas Judul yang Bersifat Redundan
- **Lokasi**: `components/landing/hero.tsx:29`, `app/login/page.tsx:163`, `app/register/page.tsx:204`, `app/laporan/page.tsx:14`, `app/petugas/laporan/page.tsx:38`
- **Aturan**: R-09 (Badges — Eyebrow Badge Above Headline).
- **Alasan**: Badge kapsul dengan titik warna atau teks `FIVORA` / `PETUGAS` diparkir tepat di atas judul H1/H2 secara berulang di setiap halaman tanpa fungsi status yang nyata.

#### 18. [R-04] Ikon Lucide Tidak Terpakai dan Glyph Generik
- **Lokasi**: `facility-showcase.tsx`, `features.tsx`, `operating-hours.tsx`, `workflow.tsx`
- **Aturan**: R-04 (Icons).
- **Alasan**: Terdeteksi 11 warning lint untuk import ikon Lucide yang tidak digunakan (`Calendar`, `Layers`, `CalendarCheck`, `AlertCircle`, `Wrench`, `ShieldAlert`). Selain itu, beberapa kartu fitur menggunakan ikon generik tanpa konteks spesifik.

#### 19. [R-10 / R-12] Penumpukan Efek Blur dan Shadow Mengambang Tanpa Alasan Elevasi
- **Lokasi**: `app/login/login.module.css:24-56`, `components/landing/hero.tsx:10`
- **Aturan**: R-10 (Glassmorphism), R-12 (Shadow).
- **Alasan**: Penumpukan efek latar belakang blur (`filter: blur(6px)` / `blur-[2px]`) bersamaan dengan shadow besar `0 20px 60px rgba(...)` menciptakan kesan visual mengambang (floating UI) tanpa fungsi elevasi fungsional.

### Prioritas RENDAH (Quality Locks — Konsistensi Sistem Desain)

#### 20. [R-20 / R-29] Inkonsistensi Palet Warna dan Motif Brand Antar Halaman
- **Lokasi**: `admin-dashboard.module.css`, `login.module.css`, `register.module.css`, `navbar.tsx`, `footer.tsx`
- **Aturan**: R-20 (Visual Identity), R-29 (Color Palette).
- **Alasan**: 
  - Admin dashboard menggunakan warna lavender terpisah (`#f6f2ff`, `#21164f`, `#7448ef`) yang tidak terhubung dengan variabel warna tema di `globals.css` (`--primary: #0c021c`, `--accent: #5318eb`).
  - Elemen logo berubah-ubah: gambar PNG di navbar, bulatan putih di login, belah ketupat di register, dan ikon gedung di footer.

#### 21. [R-05 / Aturan Bisnis] Informasi Alur Layanan Bertentangan dengan Aturan Dosen
- **Lokasi**: `components/landing/workflow.tsx:154`
- **Aturan**: R-05 (Layout & Content-Driven Composition), AGENTS.md (Aturan Fasilitas Dalam Perbaikan).
- **Alasan**: Teks menyatakan *"status fasilitas kembali otomatis menjadi 'Tersedia'"* setelah perbaikan selesai. Aturan bisnis menetapkan bahwa status perbaikan dikelola manual oleh petugas sarpras dan tidak boleh otomatis aktif kembali.

#### 22. [R-31 / DESIGN.md] File Arah Desain Masih Memuat Template Aplikasi Lain (Pitch.com)
- **Lokasi**: `DESIGN.md:3-6`
- **Aturan**: R-31 (Every Decision Must Have a Reason), R-37 (Design Direction).
- **Alasan**: Metadata `DESIGN.md` masih mendeskripsikan "Pitch is the AI presentation workspace... winning slide decks". Arah desain harus mencerminkan identitas autentik Fivora sebagai portal kampus terpadu.

#### 23. [R-25] Kontras Teks Muted Berada di Bawah Standar WCAG AA (4.49:1 vs 4.5:1)
- **Lokasi**: `components/landing/facility-showcase.tsx:173, 332`, `components/landing/footer.tsx:23`
- **Aturan**: R-25 (Color Contrast).
- **Alasan**: Penggunaan warna `#7b757d` pada latar putih memiliki rasio kontras 4.49:1, sedikit di bawah batas minimal WCAG AA untuk teks standar (4.5:1). Perlu disesuaikan menjadi minimal `#746e76` atau warna teks muted yang lebih kontras.

#### 24. [C-2 / UX] Tindakan Verifikasi Pengguna Memicu Full Browser Reload
- **Lokasi**: `app/admin/registration-list.tsx:54`
- **Aturan**: C-2 (Functional Completeness & UX Resilience).
- **Alasan**: Fungsi `updateStatus` memanggil `window.location.reload()`, menyebabkan layar berkedip dan menghilangkan state interaktif, alih-alih menggunakan `router.refresh()` atau state update optimistik Next.js.

## Panduan Tindak Lanjut

Sesuai aturan operasional antislop:
1. **Pilih nomor temuan** yang ingin diperbaiki (misalnya: `"perbaiki nomor 01, 02, 03, 04, 05, 08, 12, 14"` atau `"perbaiki semua prioritas TINGGI"`).
2. Temuan yang **tidak dipilih tidak akan disentuh**.
3. Setelah nomor disetujui, perbaikan kode akan dieksekusi dan diverifikasi ulang dengan Delivery Gate.
